# 创客互助中的披露边界与结对方案

社区共创场次、成员的授权留言及联络员回条。材料中的人、机构及经营记录是合成的。

每份资料为 UTF-8 JSON 数组。id 在同一份资料内唯一，原始文字按收到的形式保留。

- `data/messages.json`。活动协调员接收的成员原话。kind=成员回信表示本人回应，转引未必获得原发言人许可。
- `data/resources.json`。社区排班和保密记录。times 是成员报名的场次，选择同一人的两种活动会占用同一份可用容量。access 是资料所有方在报名系统已有的可见授权。
- `data/consents.json`。邀请回条。从时间线接入本次选择，accepted_for 指联络人谈到的场次和提议。
- `data/timeline.json`。协调员导出的先后回执。refs 同组在意见都收齐后处理。每份邀请的编号由受理时生成，报名时使用原来材料引用。

使用 Python 3.11 标准库，无需安装软件包或连接外部服务。

以下命令分别读取一份原始资料、检查资料中的字段与关联。

```sh
python3 -m json.tool data/messages.json
python3 -m unittest discover -s tests -v
```

## 互助工具（exchange 包）

在仓库根目录运行，按 timeline 的次序处理留言、回执与撤回，打印处理经过、
公共公告、待核实线索、可见性解释与承诺终态。

```sh
python3 -m exchange            # 使用 data/ 下的资料
python3 -m exchange 其他目录    # 使用指定目录里的四份资料
```

各模块对应的环节：

- `exchange/parsing.py`。把成员口语留言分句归类：明确能给出的帮助、真正要补的
  能力、可交换条件、许可范围；识别转述（只记为线索）、否定（不得当作供给）、
  附条件（未知则待问）与同一条留言里同时出现的供需；随后的澄清并入档案，
  许可类规则以最新一条为准。
- `exchange/confidentiality.py`。保密词表声明“哪几项合在一起能识别项目”
  （如地点加商品代号）；公开内容若凑齐组合，隐去未被允许单说的词并记录原因。
- `exchange/summaries.py`。安全摘要分公开/配对/联络人/本人四层；联络人邀请成员
  确认，确认前其他人只能看到允许公开的部分；公共公告只由公开层组成。
- `exchange/materials.py`。第三方资料的授权登记：只对指定受众和用途有效，
  不把承诺当作无条件供给；支持撤回。
- `exchange/matching.py`。结成单向协助与双方互助候选；交换条件整体满足才结对；
  未知条件与授权问题记入待问。
- `exchange/scheduling.py`。优先材料指定的先行场次，随后在不拆开互助的前提下
  尽量覆盖更多已准备的需求；同一成员的唯一时段被竞争时只排一组；提议本身
  不耗时段，锁定才占用；待问与可分别申请确认的提议分开列出。
- `exchange/commitments.py`。分别申请确认，每份邀请编号由受理时生成；参与方
  看到各自有权看到的摘要后确认；相关方都同意且资料条件满足才锁时段。撤回
  资料时，待确认邀请不再带出该资料，已约好的会面只在承诺依赖该资料时受
  影响；受影响小组可改约但须重新确认，空下的名额交回排班让给其他候选。
- `exchange/explain.py`。解释“为什么一边看得到邀请而另一边暂时看不到”：
  内部理由可引用具体规则，公开措辞不暴露差别背后的私密内容。
- `exchange/registration.py`。报名表只存项目代号与场次。
- `exchange/pipeline.py`。把以上环节按 timeline 串成端到端流程。
